# Web Security Header / TLS Audit -- dmc-new.towardpcc.com & dmc-im.com

**Scope:** Read-only, single GET on `/` per hostname (+ the redirect chain from the plain-HTTP
apex), no logins/forms/directory probing. Live headers captured via `curl` (2026-09-03,
~11:49-11:50 UTC); TLS via `openssl s_client`. Both hosts are owned/authorized by the requester
(per project CLAUDE.md -- DMC Internal Medicine, live PHI systems).

**Tools used:** `curl -sSI` / `curl -sSL -D -`, `openssl s_client` (protocol/cipher/cert), static
read of response bodies for SRI. No WAF/pentest tooling (`testssl.sh`, SSL Labs, ZAP, `smuggler.py`)
was run -- call out below wherever a finding needs one of those to move from `tentative` to confirmed.

---

## Host 1 -- `https://dmc-new.towardpcc.com/` (Laravel, Cloudflare-proxied)

**stackDetected:** languages=[php, typescript], frameworks=[laravel, inertia.js, vue], proxy=null, edge=cloudflare.
Confirmed by `Server: cloudflare`, Laravel `XSRF-TOKEN`/session cookie names, Inertia `X-Inertia`
`Vary` + `data-page="app"` JSON payload, and a per-request CSP nonce matching the repo's
`SecurityHeaders` middleware description.

**Redirect chain from plain HTTP apex:**
`http://dmc-new.towardpcc.com/` -> 301 -> `https://dmc-new.towardpcc.com/` -> 302 -> `https://dmc-new.towardpcc.com/login` -> 200.
All hops HTTPS after the first redirect -- no protocol downgrade at any point.

| Control | Observed value |
|---|---|
| **HSTS** | `max-age=31536000; includeSubDomains; preload` -- meets the 1-year floor, subdomains covered, preload flag present (HTTPS-only, redirects HTTPS end to end) |
| **CSP** | Present, nonce-based, strict: `default-src 'self'; script-src 'self' 'nonce-<random-per-request>'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; font-src 'self' data:; connect-src 'self'; frame-ancestors 'none'; base-uri 'self'; form-action 'self'; object-src 'none'; report-uri /csp-report; report-to csp-endpoint`. `script-src` has no unsafe-inline/unsafe-eval/wildcard -- nonce changes every response (3 distinct nonces observed across 3 requests). `style-src` still carries `'unsafe-inline'` with no nonce on that directive, so it is live, not CSP3-neutralized |
| **X-Frame-Options** | `DENY` |
| **X-Content-Type-Options** | `nosniff` |
| **Referrer-Policy** | `same-origin` |
| **Permissions-Policy** | `camera=(), microphone=(), geolocation=()` -- present but not exhaustive (no payment=(), usb=(), interest-cohort=()) |
| **Cross-Origin-\*** | Absent -- no COOP, COEP or CORP header observed |
| **Cache-Control (this page)** | `no-cache, private` on the login page (pre-auth, no PHI); `cf-cache-status: DYNAMIC` confirms Cloudflare did not cache it |
| **Set-Cookie: XSRF-TOKEN** | `XSRF-TOKEN=eyJpdiI6...<masked>; Max-Age=7200; path=/; secure; samesite=lax` -- no HttpOnly by design (Laravel double-submit CSRF token, must be JS-readable; not a session/auth cookie) |
| **Set-Cookie: dmc-internal-medicine-session** | `dmc-internal-medicine-session=eyJpdiI6...<masked>; Max-Age=7200; path=/; secure; httponly; samesite=lax` -- Secure, HttpOnly, SameSite=Lax all set, no Domain attribute (already host-only), but no `__Host-` prefix |
| **Server / X-Powered-By** | `Server: cloudflare` only -- no framework/version disclosure |
| **TLS** | Negotiated TLS 1.3, `TLS_AES_256_GCM_SHA384` (AEAD, forward secrecy). Cert: CN=towardpcc.com, issuer Let's Encrypt, verify return code 0 (ok). Attempts to force TLS 1.0/1.1 returned "no protocols available" from this client's OpenSSL 3.5 -- that is the local client refusing to *offer* legacy protocols, not proof the server rejects them; confidence: tentative -- confirm with testssl.sh/SSL Labs whether Cloudflare's zone minimum-TLS setting still permits 1.0/1.1 |
| **SRI** | All script/link tags are first-party, same-origin (`/build/assets/...` plus Cloudflare's own same-path `/cdn-cgi/challenge-platform/...` nonce-tagged inline script). No third-party CDN resources observed -> SRI not applicable (info) |
| **Smuggling / cache-deception indicators** | `Transfer-Encoding: chunked` used alone (no co-present Content-Length), no duplicate headers, standard Cloudflare edge framing -- no CL/TE ambiguity visible. `cf-cache-status: DYNAMIC` + `Cache-Control: private` rules out cache deception on this path. Origin<->Cloudflare leg not visible from outside (tentative) |

### Verdict: Grade A

Strong, deliberately-hardened posture (nonce CSP, frame-ancestors 'none', full session-cookie flag
set, 1-year preloaded HSTS, TLS 1.3/AEAD). Held back from A+ by three small, easy fixes:

**Top 3 findings**

1. **SPC-WEB-001 (low)** -- Session cookie not using the `__Host-` prefix. CWE-1275 / OWASP Secure
   Headers (Session Mgmt) / MDN Set-Cookie.
   Evidence: `Set-Cookie: dmc-internal-medicine-session=...; path=/; secure; httponly; samesite=lax` (no Domain, so it already qualifies for the prefix).
   Fix: rename the cookie to `__Host-dmc-internal-medicine-session` (Laravel: `SESSION_COOKIE=__Host-dmc-internal-medicine-session` in `.env`, keep `path=/`, no Domain). Locks the cookie to this exact host and blocks subdomain/cousin-domain cookie injection.

2. **SPC-WEB-002 (low)** -- No `Cross-Origin-Opener-Policy` / `Cross-Origin-Resource-Policy` on an
   authenticated PHI application. CWE-200 / MDN COOP/CORP.
   Evidence: neither header present in any captured response.
   Fix: `Cross-Origin-Opener-Policy: same-origin` and `Cross-Origin-Resource-Policy: same-origin`
   (add via the existing SecurityHeaders middleware alongside the CSP/HSTS lines).

3. **SPC-WEB-003 (low)** -- CSP `style-src` still allows `'unsafe-inline'` (not neutralized -- no
   nonce on style-src). CWE-1021 / OWASP Secure Headers CSP.
   Evidence: `style-src 'self' 'unsafe-inline'`.
   Fix: reuse the same per-request nonce already generated for script-src on style-src
   (`style-src 'self' 'nonce-<same-random>'`) or hash the few inline `<style>` blocks Tailwind/Inertia
   emit; drop `'unsafe-inline'` once verified nothing else relies on it.

*(Minor/info, not in the top 3: Permissions-Policy doesn't cover payment=()/usb=()/interest-cohort=();
login-page Cache-Control is `no-cache, private` rather than `no-store` -- low impact since the page
carries no PHI.)*

## Host 2 -- `https://www.dmc-im.com/` (legacy PHP, SiteGround shared hosting)

**stackDetected:** languages=[php], frameworks=[adminlte, bootstrap5, jquery], proxy="nginx (SiteGround Site Tools/CDN)", edge=null.
Confirmed by `Server: nginx`, `X-Httpd-Modphp: 1`, SiteGround `X-SG-CDN`/`X-CE`/`X-Proxy-Cache*`
headers, `PHPSESSID` cookie, AdminLTE/Bootstrap/jQuery vendored asset paths in the login page --
matches CLAUDE.md's description of this as the original, un-hardened legacy app, not the
`renovation` hardening branch.

**Redirect chains observed (all requested entry points):**
- `http://dmc-im.com/` -> 301 -> `https://dmc-im.com/` -> 301 -> `http://www.dmc-im.com/` -> 301 -> `https://www.dmc-im.com/` -> 200
- `https://dmc-im.com/` (direct) -> 301 -> `http://www.dmc-im.com/` (same downgrade hop, reproduced independently)
- `https://www.dmc-im.com/` (direct) -> 200 immediately

**The canonical redirect chain includes a live HTTPS-to-HTTP downgrade**: `https://dmc-im.com/`
301-redirects to plaintext `http://www.dmc-im.com/` before that in turn 301s back to HTTPS.
Reproduced twice (full-chain run and a direct single-hop run against the bare HTTPS apex).

| Control | Observed value |
|---|---|
| **HSTS** | Absent on every response captured -- apex and www, HTTP and HTTPS, all hops |
| **CSP** | Absent |
| **X-Frame-Options** | Absent |
| **X-Content-Type-Options** | Absent |
| **Referrer-Policy** | Absent |
| **Permissions-Policy** | Absent |
| **Cross-Origin-\*** | Absent (COOP/COEP/CORP) |
| **Cache-Control (this page)** | `no-store, no-cache, must-revalidate` + `Pragma: no-cache` -- correctly non-cacheable (the one control that is right) |
| **Set-Cookie: PHPSESSID** | `PHPSESSID=<masked-32-hex>; path=/` -- no Secure, no HttpOnly, no SameSite at all |
| **Server / X-Powered-By** | `Server: nginx` (no version) but `X-Httpd-Modphp: 1`, `X-CDN-C`, `X-SG-CDN`, `X-CE: europe-west3-*`, `X-Proxy-Cache*`, `Host-Header: 8441280b...` -- SiteGround internal proxy/PoP/cache-key topology leaked to every client |
| **TLS** | Negotiated TLS 1.3, `TLS_AES_256_GCM_SHA384` (AEAD). Cert: CN=*.dmc-im.com, issuer Let's Encrypt, verify return code 0 (ok) for both dmc-im.com and www.dmc-im.com SNI. Same client-side caveat as Host 1: TLS 1.0/1.1 offer could not be tested from this OpenSSL build (tentative, confirm with testssl.sh/SSL Labs) |
| **SRI** | All script/link tags are same-origin relative paths (`vendor/jquery-3.7.1.min.js`, `vendor/bootstrap-5.3.3-dist/...`, `dist/css/adminlte.min.css`) -- no third-party CDN, so SRI is not the primary gap; but the relative vendor paths do disclose exact library versions (jQuery 3.7.1, Bootstrap 5.3.3, Font Awesome 6.5.2) for fingerprinting |
| **Smuggling / cache-deception indicators** | No duplicate Content-Length/Transfer-Encoding conflict observed; SiteGround's `X-Proxy-Cache: MISS` / `X-Proxy-Cache-Info: ...UP:SKIP_CACHE_SET_COOKIE` shows the front cache correctly refuses to cache Set-Cookie responses (one small positive). True request-smuggling reachability is unconfirmed from headers alone -- tentative, needs smuggler.py/Burp against the authorized host |

### Verdict: Grade F

Essentially the entire response-header security suite is missing, the primary session cookie is
unprotected, and the site's own canonical redirect chain bounces through plaintext HTTP -- on a
live system holding real PHI. This matches CLAUDE.md's stated ground truth that dmc-im.com is
still running the original, un-hardened legacy build, not the renovation hardening.

**Top 3 findings**

1. **SPC-WEB-001 (critical)** -- No HSTS anywhere, combined with a session cookie (PHPSESSID)
   missing Secure/HttpOnly/SameSite, evidenced by a live protocol downgrade in the site's own
   canonical redirect chain (`https://dmc-im.com/` -> 301 -> `http://www.dmc-im.com/`).
   CWE-319 + CWE-614 + CWE-1004 / OWASP Top 10:2025 A02 (Security Misconfiguration / Crypto
   Failures) / NIST SP 800-52r2 / PCI-DSS Req 4.
   Evidence: `Location: http://www.dmc-im.com/` on a 301 served over HTTPS at `https://dmc-im.com/`;
   `Set-Cookie: PHPSESSID=<masked>; path=/` with no secure/httponly/samesite.
   Impact: because there is no HSTS, a browser follows that redirect over plaintext HTTP with no
   warning; because the cookie has no Secure flag, if a session already exists it will be sent in
   cleartext on that hop -- a textbook SSL-stripping / session-hijack path over a PHI system.
   Fix: `Strict-Transport-Security: max-age=63072000; includeSubDomains` on every HTTPS response
   (Apache/.htaccess: `Header always set Strict-Transport-Security "max-age=63072000; includeSubDomains"`),
   fix the redirect so `https://dmc-im.com/` goes straight to `https://www.dmc-im.com/` (never
   through http://), and set the session cookie flags -- PHP: `session.cookie_secure=1`,
   `session.cookie_httponly=1`, `session.cookie_samesite=Lax` in php.ini, or
   `session_set_cookie_params(['secure'=>true,'httponly'=>true,'samesite'=>'Lax'])` before
   `session_start()`.

2. **SPC-WEB-002 (high)** -- The entire response security-header suite is absent on the
   authentication page: no CSP, X-Frame-Options, X-Content-Type-Options, Referrer-Policy, or
   Permissions-Policy. CWE-1021 / CWE-430 / CWE-200 / OWASP Secure Headers Project.
   Evidence: none of these headers appear in any of the six captured responses for this host.
   Impact: no clickjacking defense on the login form, no MIME-sniffing protection, no baseline
   XSS defense-in-depth.
   Fix (shared-hosting .htaccess, since this is SiteGround shared hosting -- no nginx.conf access):
   ```
   Header always set X-Frame-Options "DENY"
   Header always set X-Content-Type-Options "nosniff"
   Header always set Referrer-Policy "strict-origin-when-cross-origin"
   Header always set Permissions-Policy "camera=(), microphone=(), geolocation=(), payment=()"
   Header always set Content-Security-Policy "default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; frame-ancestors 'none'; object-src 'none'; base-uri 'self'"
   ```
   (Start CSP in Content-Security-Policy-Report-Only first given the inline style/vendor script
   layout, then tighten and enforce.)

3. **SPC-WEB-003 (low)** -- Backend/library version and hosting-topology fingerprinting.
   CWE-200 / OWASP Secure Headers Project.
   Evidence: vendored asset paths (vendor/jquery-3.7.1.min.js, vendor/bootstrap-5.3.3-dist/,
   vendor/fontawesome-free-6.5.2-web/) name exact client-library versions; response headers
   X-Httpd-Modphp: 1, X-CE: europe-west3-*, Host-Header: 8441280b0c35cbc1147f8ba998a563a7,
   X-Proxy-Cache* leak SiteGround's internal PoP/cache-key/backend identifiers.
   Fix: rename/hash vendored asset directories at build/deploy time (or route them through a
   version-agnostic path); the SiteGround X-* headers are largely outside app control on shared
   hosting -- file a support request with SiteGround to suppress X-Httpd-Modphp/Host-Header/X-CE
   on client-facing responses, or front the site with Cloudflare (already used for Host 1) to
   strip them at the edge.

*(Not in the top 3 but noted: request-smuggling reachability on the SiteGround
front-proxy<->PHP-FPM chain is unconfirmed from headers alone -- confidence: tentative, would need
smuggler.py/Burp HTTP Request Smuggler against the authorized host to confirm or rule out.)*
